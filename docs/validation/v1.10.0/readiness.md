# 理性失序 1.10.0 · 实施与验收记录

日期：2026-11-07。范围：独立本地文本知识库，四角色、材料整理、关系和资产迁移。运行环境：Windows、Node 24.21.0；浏览器验收使用专用合成示例目录，未迁移真实个人知识库。

## 评估后的取舍

保留已经验证的统一对象解析、原身份、中文检索、支持/反驳论证、来源核对、受审阅的 Agent 变更、文件版本保护和事务恢复。可选 Obsidian 入口继续存在。

升级了原先不足的环节：

| 原先的问题 | 本版行为 |
| --- | --- |
| 导航围绕阅读、推演和提案，缺少四板块的协作 | 四角色导航，共享全部资产与待整理材料；多角色不重复建立身份 |
| 材料只能当普通笔记，缺少明确的整理路径 | 原文收集 → 可解释的段落建议 → 人工选择角色 → 带原文版本和行范围的知识单元 |
| 关系主要依赖手写 Markdown | 界面及 Agent 提案支持六种有向关系，理由随内容保存，相似线索单独显示 |
| 点状图难以直接支持判断 | 保留论证图；新增角色分组和重复模式的案例/反例对照表 |
| 内容与关系不便迁出 | JSON、CSV、Markdown/Mermaid、带哈希的 Markdown 知识 ZIP，导入先预览冲突 |
| 状态切换反馈不足 | 180 ms 页面/对话框过渡、120 ms 控件反馈；减少动态效果时关闭动效 |

实施设计：[三层设计 v1.0](../../architecture/three-layer-design-v1.0.md)。操作与字段：[四板块工作区](../../four-role-workspace.md)。

## 自动化与工程验证

最终 `npm run validate` 退出码 0，完整日志：[full-validation.log](full-validation.log)。

- TypeScript：58 个测试文件，**655 项通过**。
- Python projector：20 项通过；mutation gate：42 项通过。
- 合计 **717 项自动化测试**，包含新功能的 21 项后端回归、2 项动效偏好检查、1 项材料草稿保护回归。
- 类型检查、插件和独立运行时构建、插件产物检查、隔离目录运行检查均通过。独立运行时无需 node_modules；30 项运行文件及哈希：[artifacts.json](artifacts.json)。
- 另外用构建后的 Node 运行时实际连接 MCP stdio：分析材料、提取提案、拒绝未批准应用、本地签署后由 Agent 应用、四角色查询及导出均通过：[mcp-four-role.json](mcp-four-role.json)。
- 1000 份混合格式合成笔记：初始索引约 723 ms，检索 P50 约 395 ms、P95 约 427 ms；外部编辑刷新通过。每次查询包含磁盘核对：[scale.json](scale.json)。这是单机工程规模检查。

新增回归重点：多角色和旧 ID、未分类材料、精确引用、代码块与否定措辞、重复采纳、原文/证据过期、并行采纳提案、角色编辑保留正文、六种关系方向和理由、知识包往返、同名/身份冲突、包哈希和大小边界、目录穿越、公式与 Mermaid 文本、只读服务及 Agent 权限边界。

收尾时发现并修复了“摘录单元的后继修订复制提取唯一标记，从而被重复采纳检查拦截”的问题。后继保留角色和引用，原单元保留提取标记；正常修订和再次采纳保护均有回归覆盖。

## Eval

- 原有固定检索语料：12 份文档、26 条查询（含 1 条预期空结果）。当前正例 Recall@5 与 MRR@5 均为 100%，预期空结果及来源/反例/预算检查通过；旧算法基线仍可重放。
- 新增 10 条开发者编写的合成分类样本：角色集合、未分类弃权和引用行范围检查通过：[role-eval.json](role-eval.json)。规则版本为 `paragraph-rules/1`。

上述数据用于开发回归。它们不代表真实用户语料上的准确率，不证明模式或内容为真，也没有测试真实模型的回答质量。没有进行原生 Obsidian 的同条件质量对比。

## 尚需真实使用验收的部分

规则分类的语义能力有限；用户可以人工修正，外部 Agent 可以提交自己的分析，但服务没有内置推理模型。跨案例模式由用户声明与比较，不自动发现或验证因果。

知识包是 Markdown 内容迁移，不含附件、密钥及执行历史；PDF/OCR、跨设备同步、长期崩溃/断电实机测试、真实个人资料和模型质量评估仍未完成。本次通过的工程验证不替代这些验收。
