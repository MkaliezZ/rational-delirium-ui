# 1.9.0 独立知识库：eval、改造与验收

日期：2026-11-07。范围：本地文本知识、Agent 读写接口、来源核对、受控修订与独立 UI。状态：本机工程验收通过；真实资料、长期使用、模型问答和用户审美验收仍需分别验证。

## eval 后的取舍

| 评估项 | 观察 | 本版决策 |
| --- | --- | --- |
| Markdown、稳定 ID、双格式解析 | 能保留旧身份，来源可追溯，重复身份不会任意选取 | 保留并由独立服务复用同一索引 |
| 支持、反驳、未解析关系 | 固定任务能同时保留分歧和缺失来源 | 保留；context 优先为分歧和身份分配空间，并提供声明出处 |
| 子串匹配与路径排序 | 正文偶然提及会压过标题，旧版本排在当前版前；中文连写查询漏检 | 升级为分词、BM25、标题/作者别名加权及温和的当前版本偏好 |
| 精确 ID 查询 | 初版分词会把共享日期的其他对象带入结果 | 改为精确身份查找；缺失 KO ID 不退化为日期碎片搜索 |
| 写入与审阅 | 原有 Obsidian 人工操作和 append-only gate 不足以提供独立的通用修订闭环 | 新建内容绑定的提案、签名决定、源版本核对和事务日志；旧流程仅保留兼容 |
| 关系导航 | 点云距离不能直接表达证据含义 | 采用观点、支持、反驳、其他来源的分组论证图，摘要与来源可直接核对，提供列表备选 |
| 分散视图 | 阅读、来源和协作需要多个入口；专用 Loop 视图尚无真实使用证据支持其独立价值 | 合并主要任务入口，保留原始 Loop 对象和声明，不删除既有资料 |
| 老 Agent 文档 | 默认依赖 Obsidian，且与新执行方式冲突 | 更新当前工作流，旧文档归档；历史兼容测试明确指向旧契约 |

关系显示方式是设计改造，尚未做真人与点云图的任务耗时对照，因此不宣称已经证明其效率优于 Obsidian。Markdown 可移植性也不是本产品独有优势。

## 固定检索与上下文 eval

语料：[corpus.json](../../../eval/corpus.json)。包含 KO、旧格式证据、普通笔记、近似标题、历史版本、作者声明别名、支持与反驳、缺失引用，以及检索干扰项。

最初 20 个探索用例过于偏重现成词句；在算法改造前补充了 6 个中文连写/自然表达任务。最终为 **25 个有相关来源的查询 + 1 个应无结果查询**。这是自建开发集，不是盲测集或真实用户语料。

基线是 eval 开始时的独立读取原型：AND 子串匹配、按路径排序。**它不是原生 Obsidian 搜索的成绩**；1.8.0 当时没有可用同一接口调用的独立搜索服务。冻结的 [基线算法](../../../eval/baselines/knowledge-v0.mjs) 从改造前的构建中保存，解析/文件边界依赖共用代码。

| 指标 | 基线 | 当前 |
| --- | ---: | ---: |
| Recall@5，25 个正例的平均相关来源覆盖 | 76.0% | 100.0% |
| MRR@5，25 个正例的平均首个相关结果倒数名次 | 70.0% | 100.0% |
| 严格标签下的返回结果精度，最多 5 条 | 70.7% | 86.7% |
| 1 个应无结果任务 | 通过 | 通过 |
| 焦点、支持、反驳、缺失来源、预算、旧身份检查 | 6/6 | 6/6 |

来源：[基线结果](baseline-eval.json)、[当前结果](current-eval.json)。两份结果记录相同语料与基线算法哈希。`npm run eval` 会重新构建基线快照和当前实现；不依赖开发机遗留的缓存 bundle。普通 eval 输出到 `.tmp/eval`；`npm run eval:record` 才更新文档中的验收快照。

早期进度中汇总为 76.9%/71.2%，当时把“应无结果”用例也计进了 Recall/MRR。最终将负例单独统计，使用上表标准分母。[最初 20 条探索记录](baseline-initial20-eval.json) 仅为历史过程，不能与最终 26 条任务直接比较。

这些结果支持本版检索改造在固定任务中的收益，不证明任意语义改写都能检索、不证明来源正确，也不证明模型回答忠实。没有执行真实 LLM 答案评测。

## 规模与运行边界

[千篇测试](scale.json) 使用 1,000 个混合格式合成对象，逐请求完整磁盘核对，测得建索引约 0.71 秒、查询 P50 约 0.36 秒、P95 约 0.41 秒；外部修改能被后续查询读取。此为本机单轮数据，不是大库或长期耐久承诺。

当前明确限制：单篇 Markdown 2 MiB，提案 8 MiB / 32 个文件，恢复日志（含旧快照）31 MiB，已索引文本总量 256 MiB，最多 50,000 篇。无法读取的知识源会阻止需要完整身份核对的写入。越界时拒绝操作，不静默提交半个知识库。

多文件变更是合作式锁与日志支持的恢复流程，不是跨文件 OS 原子事务；第三方写者不受该锁控制。签名绑定内容，不能证明操作者必定为人，也不能隔离拥有完整磁盘权限的 Agent。Windows 文件 fsync 不等于断电耐久保证。

尚未覆盖：真实个人资料的相关性标注与留出集、真实 Agent 回答忠实性、多日并发/断电耐久、原生移动端、多设备同步、PDF/OCR、附件预览、跨操作系统视觉一致性。备份与操作者密钥恢复安排仍由用户管理。

结论：本版具备可独立启动、可供 Agent 查询及受控修订的完整文本知识闭环。后续质量判断应来自真实使用数据，而不是把固定测试的通过率等同于知识库整体成熟度。
