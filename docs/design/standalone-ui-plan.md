## 1. 产品与视觉原则

产品是可独立运行、供人和 Agent 使用的个人知识库。Markdown 保存原始知识；界面帮助人查找、阅读、追溯与修订。Obsidian 是可选入口，不是必需运行环境。

「理性」体现在清楚的层级、稳定身份、真实来源、可理解的操作结果。「失序」体现在标题的文学感、关系探索的非对称构图和少量有张力的强调。正文、标识与操作保持稳定，不使用抖动、故障文字或持续运动表达品牌。

日常默认进入知识库并恢复上次阅读位置；效果图里的推演页是核心场景之一。界面不靠统计面板或装饰性大图填满空间。长篇边界说明折叠为就近可读的帮助，影响当前操作的原因直接展示。

### 保留、升级与合并

| 现有设计或能力 | UI 决策 | 原因与约束 |
| --- | --- | --- |
| 深炭色、纸色文字、衬线标题、精确 ID | 保留并提高可读性 | 有辨识度，也适合来源阅读 |
| 显式支持、反驳、派生关系 | 保留，增加就近来源定位 | 关系来自声明；关系数量不等于可靠程度 |
| 左索引、中央内容、右 Inspector | 升级为可折叠的共用三栏 | 三条主任务保持位置与操作习惯一致 |
| Archive Home、Knowledge Panel、Context 等分散入口 | 合并到「知识库」与其来源侧栏 | 阅读与证据不再需要反复换视图 |
| Investigation、Graph Intelligence、Loop | 汇入「推演」中的任务与关系探索 | 是否保留为子视图取决于 eval 中是否有独立价值 |
| Collaboration、提案、贡献记录 | 合并到「Agent 提案」，历史可追溯 | 给出改动、依据、状态与执行结果 |
| 大片绿色、过量元数据、常驻诊断文本 | 替换或按需展开 | 减少干扰，聚焦内容与当前任务 |

这些是设计假设。界面是否更好用，要由后文任务验收验证；不会因为效果图更漂亮就删除有价值的能力。

## 2. 信息架构

顶部只保留品牌、三个主入口、全局搜索和修订历史入口。

| 位置 | 入口 | 主要任务 |
| --- | --- | --- |
| 顶部主导航 | 知识库 | 找、读、记录、编辑知识和普通笔记 |
| 顶部主导航 | 推演 | 围绕一个问题比较观点，查看声明关系和分歧 |
| 顶部主导航 | Agent 提案 | 查看 Agent 打算改什么、为什么改，审阅并跟踪结果 |
| 顶部工具 | 搜索、修订历史 | 全局定位；查看当前对象或全库的历史 |
| 左下角工作区菜单 | 工作区、导入、Agent 接入、设置 | 选择本地资料位置，配置连接与显示 |

首版不把对话框作为首页。Agent 可从同一知识服务获取资料和提出改动；是否增加内置问答，由检索、来源覆盖与回答忠实性 eval 决定。

### 共用布局

桌面参考视口 1440 × 1024：顶部 64px；左索引 248px；右侧来源面板约 360px；中央使用剩余空间。两侧可收起，右栏可调宽。主内容边距 24–32px，缩小屏幕先收起辅栏，不压缩正文到难以阅读。

- 左栏随任务改变内容：知识列表、研究线索或提案列表，保留当前筛选与滚动位置。
- 中央始终是主要工作：文章、局部关系图或修改对比。
- 右栏始终用于核对：来源原文、关系声明位置、变更依据、版本信息。
- 返回、前进和页面刷新恢复对象与视图状态。对象通过稳定 ID 定位，普通笔记通过路径定位；重命名或删除后显示真实结果。

## 3. 三条核心流程

### 知识库：搜索 → 阅读 → 定位来源 → 编辑或引用

全局搜索接受标题、正文、ID；结果展示命中片段、对象类型、文件位置和必要的修订状态。普通 Markdown 笔记可检索，不强迫用户先补齐对象元数据。相关性排序标为检索行为，不显示虚构的可信分。

阅读页优先展示标题、正文、少量身份信息。支持、反驳、历史版本、原始字段按需展开。点击引用在右栏定位原文和行号；可复制包含 ID、文件与版本的引用。元数据无效或 ID 冲突时仍可通过路径读原文件，清楚说明不能可靠定位对象的原因。

人直接编辑自己的笔记使用普通保存流程，不为每次编辑增加审批。首次创建以标题与正文为主；需要建立关系或提供给 Agent 稳定引用时，再明确身份字段。保存前检查当前文件版本；外部更改发生时提供对比，保留未保存内容。

### 推演：选问题 → 看局部关系 → 比较分歧 → 回到原文

保留选中效果图的核心构图：左线索、中央焦点对象及局部关系、右证据原文。默认只展开一跳，按需继续探索，显示省略或未解析的关系。稠密时提供同等可用的关系列表，不以大量节点压缩可读性。

节点点击与键盘选择只改变阅读焦点；不会提升知识等级。连线方向忠于声明，边的来源可定位到文件、字段与行。跨两条关系不自动推导新事实。支持与反驳同时可见；旧版本、来源缺失和 ID 歧义有独立文字状态。

中央下方的「保留的分歧」按原始声明列出，摘要不能悄悄替代原文。右侧「打开原文」在应用内打开对应笔记并定位，不依赖 Obsidian。

### Agent 提案：看改动 → 核对依据 → 决定 → 追踪执行

提案详情先展示具体改动和目的，再展示 Agent、对象、引用与时间。中央是可读的前后对比；右栏是依据。新增、删去、未变的内容分别有文字和视觉标记，不能只靠红绿区分。

「批准」记录对所展示版本的决定；「应用更改」承担真正写入。默认分开两步，批准后的主动作明确切换为应用；执行结果由服务返回。提案被修改、原文件发生变化或依据不可读取时，重新核对范围并呈现真实状态，不沿用失效决定。

主要状态：待审阅、已批准待应用、已拒绝、应用中、已应用、因版本变化未应用、执行失败、需要恢复。展示“已批准”不能假装“已写入”。历史记录连接提案、决定、实际变更与旧版本。撤回通过可核对的恢复变更完成，不静默覆盖之后的编辑。

## 4. 配色与字体

### 候选颜色 Token

| 用途 | 颜色 | 使用原则 |
| --- | --- | --- |
| 主背景 | `#11110F` | 深炭色，保留原产品氛围 |
| 辅助表面 | `#1D1C19` | 侧栏、轻量悬浮层 |
| 分隔线 | `#3D3933` | 装饰性细线，不独自承担控件识别 |
| 正文 | `#E9E5DA` | 暖纸色 |
| 次级文字 | `#ADA69B` | 可读的说明与元数据 |
| 品牌强调、当前选中、主动作 | `#ED754E` | 橙红，仅局部使用；按钮配深色字 |
| 键盘焦点 | `#F4AA86` | 独立轮廓与偏移，区别于当前选中 |
| 支持与一般关系 | `#C9C1B4` | 暖灰，配明确关系文字 |
| 反驳关系 | `#E79A8E` | 珊瑚红，配“反驳”及线型差异 |
| 来源待补、身份待确认 | `#D9AA70` | 琥珀文字，说明具体原因 |

不使用绿色作为主强调或默认“正确”提示。品牌橙红不等于错误；反驳不等于出错。操作成功用“已保存/已应用”等文字和时间表达，失败使用错误图标、原因和可执行动作。

对不透明色块的计算：正文/主背景约 15.02:1，次级文字/主背景 7.84:1，次级文字/辅助表面 7.06:1，橙红/主背景及深色按钮文字/橙红底 6.53:1，珊瑚红/主背景 8.47:1。这只是候选色的计算，不代表成品已通过可访问性验收。实际 hover、选中和错误状态仍需检查。

### 排版与密度

- 中文大标题使用宋体或相近衬线；日常页面 32–40px，效果图里的超大标题只作为方向参考。长标题允许换行。
- 正文使用清楚的中文无衬线，16px、行高约 1.7；界面文字 14–15px；元数据 12–13px，可随系统缩放。
- 字体离线可用，缺字使用系统回退。ID 用独立的等宽排版回退，不能影响中文可读性。
- 4px 间距基准，主要采用 8/12/16/24/32px。控件最小点击区域约 36px，触屏提高到 44px。
- 小圆角与细边框，不叠加发光、玻璃或大面积渐变。界面内不堆满英文大写元数据。
- 竖排 DELIRIUM 只作为宽屏空白边缘的可选装饰，空间不足时隐藏，不压缩来源阅读。

## 5. 交互、刷新与状态

搜索、切换对象、打开引用和刷新均可用键盘完成。默认 `Ctrl/Cmd+K` 打开搜索；输入期间不截获普通编辑快捷键。图之外必须提供关系文本列表。短过渡约 120–180ms，遵守减少动态效果设置，不自动平移或漂浮。

| 情况 | UI 应有表现 |
| --- | --- |
| 读取中 | 保留当前布局并标明读取中，避免面板闪空 |
| 没有知识 | 展示新建笔记与导入入口，不生成假对象 |
| 搜索无结果 | 保留查询，提供清除筛选和搜索范围说明 |
| 普通笔记未声明对象 | 正常阅读与搜索，关系能力按实际可用性展示 |
| 来源缺失或无法读取 | 保留引用及路径，显示具体原因 |
| 重复 ID、无效元数据 | 不任意挑一个对象；允许按路径检查来源 |
| 外部文件改变 | 阅读态更新并提示；编辑态保留草稿并要求对比 |
| 刷新失败或服务断开 | 保留已读取内容并标明可能过期，暂停依赖新状态的写操作 |
| 提案执行中 | 防止重复提交，退出后可重新查询实际结果 |
| 执行结果不确定 | 明确需要核对/恢复，不展示成功或自动盲目重试 |

宽屏显示三栏。约 1100px 以下来源改为可关闭侧抽屉；约 800px 以下索引也收起，默认单栏阅读，关系可切换列表。手机首版以查阅与审阅为主；完整触控图谱和原生客户端不作为首版前提。最终断点随实际内容验证调整。

## 6. 实现与 eval 衔接

当前仓库已经有统一索引与旧版视图；`standalone/` 目前只是未经完整验证的基础代码，尚无完整独立应用。本文不宣称独立服务、审阅执行或该 UI 已经完成。

实现时按一套知识服务连接 Web UI、CLI/Agent 入口和可选 Obsidian 入口，共用解析、索引、来源与修订语义。浏览器通过本地服务访问知识，不直接读写任意磁盘路径。图形状态是派生数据；笔记和受控变更记录才承担相应保存责任。

### 顺序与交付

1. **任务 eval 基线。** 固定语料与任务，记录检索、来源、分歧、旧版本、刷新和写入恢复的现状。形成“保留/升级/合并”记录，不能拿现有功能测试数量替代任务质量。
2. **视觉校准与组件。** 以本次橙红参考校准颜色、密度与三栏壳；先做知识阅读、搜索、来源定位的可操作闭环。
3. **关系推演。** 接入真实声明和来源，补关系文本列表、缺失来源和身份冲突状态。
4. **Agent 提案与历史。** 接入真实对比、审阅、版本校验、执行、结果查询与恢复；不以模拟成功替代写入结果。
5. **整体验收。** 同一语料与任务复测，比较前后指标；再做界面尺寸、键盘和中断恢复检查，交付可独立启动的知识库。

视觉确认只决定呈现方向，不豁免 eval 或真实流程实现。

### 任务级 UI 验收

| 任务 | 验收依据 |
| --- | --- |
| 找到特定知识及其相近标题 | 按题目记录命中、误选、步骤与耗时；ID 精确检索不能混淆 |
| 中文同义/改写查询 | 固定相关性标注，记录 Recall@k、排序与无命中；不从效果图推断检索效果 |
| 阅读知识并定位原始段落 | 引用对应正确文件、行和版本；可从摘要返回完整原文 |
| 发现支持与反驳 | 同时覆盖已声明的两侧，不把另一侧藏在只显示支持的默认视图中 |
| 检查过时、缺失和重复对象 | 状态可辨，来源可查，不自动选错对象或丢弃历史 |
| 修改笔记期间收到外部更改 | 不丢草稿、不覆盖新版本；对比后再决定如何保存 |
| 审阅并应用 Agent 改动 | 所见版本等于决定和执行绑定的版本；分别检查批准、未执行、执行结果 |
| 中途刷新、服务重启或写入失败 | UI 恢复真实状态，失败路径可解释和继续处理 |
| 无鼠标、窄屏与文本放大 | 核心任务可完成，焦点可见，正文与动作无截断遮挡 |

自动化检查可覆盖定位和状态一致性；实际人的操作体验需另做走查。没有真实模型回答评测时，不声称已经验证 Agent 问答忠实性或优于 Obsidian。
