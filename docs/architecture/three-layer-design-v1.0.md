# 理性失序 · 三层设计 v1.0

状态：2026-11-07 用户确认后实施。详细推导见 [三层发展方案](three-layer-development-plan.md)。本文件保存本轮实现的产品约定。

## 审美层：帮助用户解决什么问题

让杂乱的经历、资料和想法逐步成为能追溯、能比较、能修订的理解。用户需要回答：发生了什么，有什么依据，有哪些解释，哪些现象在重复，下一条材料会改变什么。

四个板块相互支持：CASE 案例与情境、EVIDENCE 证据与依据、HYPOTHESIS 假设与解释、LOOP 重复模式。它们是知识的用途，不是四个互斥文件夹。一份材料可以产生多个知识单元，一个单元可以承担多个角色；原文保留一份。资料暂时无法归类时，也能保存、搜索和阅读。

界面以问题和来源为中心：四个角色入口、共享材料库、假设的支持/反驳视图、模式的跨案例对照。关系以有名称、有方向、可打开原始声明的方式呈现。候选分类和相似线索与正式知识关系分开。

## 功能层：让这个过程可操作

1. 收集文字材料，保留原文。
2. 根据段落和标题提供可解释的角色建议；允许弃权和人工改选。规则建议不冒充模型推理。
3. 用户确认后，从精确的原文行范围建立知识单元，记录路径、原文版本和引用文字。重复收录有检查。
4. 四个角色共享同一索引、搜索、读写和刷新流程。既有两种对象格式继续读取，角色作为可选元数据补充。
5. 用户或 Agent 提出有方向的语义关系，使用原有审阅、批准、执行和恢复流程。相似性只能产生相关候选。
6. 原文被外部修改后，引用显示版本变化；旧摘录保留，引用不悄悄改写。
7. 导出带身份、角色、版本、引用和关系声明的 JSON、CSV、Markdown/Mermaid，以及包含 Markdown 原文的知识包。知识包导入先预览冲突，再沿用变更事务。

## 资产层：用户拥有和可以带走的内容

资产包括原始材料、知识单元、已采纳的角色与关系、引用和版本信息。Markdown 是内容来源，索引可重建。知识包不携带本机批准私钥和执行权限；历史事务保留在原工作区。知识包是内容迁移包，不等同于完整灾备。

采用可选字段 `rd_roles`、`rd_sources`、`rd_extraction_key`，沿用已有 `type/id` 或 `kind/object_id`。提取引用含 `path/revision/startLine/endLine/quote`。不在读取时补 ID，不用类型名称推断事实真伪，不自动将 process 当作 LOOP。

## UI 与动效约定

沿用已选定的深色档案室风格、暖纸色文字、橙红强调色和中文衬线标题。主色用于选择、当前焦点和重要动作；反驳使用细线和文字标签。

页面进入约 180 ms，小幅位移和淡入；来源展开约 180 ms；按钮与选中反馈约 120 ms。动效表达位置与状态变化，不持续闪烁、漂浮或自动移动内容。遵守 `prefers-reduced-motion`，键盘焦点和草稿不随重绘丢失。

## 本轮验收及后续边界

本轮交付四角色浏览、文字材料整理、来源追溯、关系编辑和导出/导入，沿用独立服务与 Agent 接口，并验证旧格式、外部刷新、并发/过期保护、事务恢复和窄屏。

分类评估使用明确标注的合成样本；现有检索评估保留旧基线。真实个人资料的分类质量、长期使用效果及模型推理质量，需要后续真实语料验收。PDF/OCR、附件迁移、跨设备同步和自动证明模式属于后续能力，不在本轮完成范围内。
